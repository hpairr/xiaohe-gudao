# 七枚二维码与固定入口（/go/ 短链）

> 用途：毕设展板／展签／桌卡上的七个码——**1 个主页 + 6 个专题**。
> 核心要求：**站点以后怎么改版，已经印出去的码都要能扫。**

## 2. 为什么更新之后还能用

```
二维码  ──固定──▶  /go/nushu/           （go/nushu/index.html，一页跳转）
                        │
                        └──可变──▶  ../../themes/02-女书.html
```

- 印在纸上的是**跳转页的地址**，不是专题页的地址。
- 专题页改名、挪目录、重写内容，只改跳转页里的那一个 `target`；
  **二维码本身不用重印**。
- 跳转页只有一个 `<meta http-equiv="refresh">` 和一个 `location.replace()`，
  权重低、`noindex`，不会被搜索引擎收录成重复页。
- 跳转目标用**相对路径**（`../../themes/...`），本地双击、换域名、换仓库都能用。

> ⚠️ 唯一会让已印的码失效的操作：**改 GitHub 用户名、改仓库名、换自定义域名**。
> 这三件事会改掉域名或仓库前缀，届时只能重印。除此之外都不影响。

## 4. 日常怎么改

### 只改内容（最常见）

直接改 `themes/*.html`、`database.html` 都行，**二维码不用动**。

### 专题页改名 / 挪位置

1. 打开 `qr/links.json`，把对应条目的 `target` 改成新路径（相对站点根目录），例如
   `"target": "themes/05-风雨桥-新.html"`。
2. 运行：

```powershell
cd xiaohe-gudao-db
python tools/make_qr.py
```

脚本会重写 `go/*/index.html` 的跳转目标，并重算二维码、逐张扫码自检。
**只要 `slug` 不动，二维码图片一个像素都不会变**，纸上的码继续有效。

> 只想改跳转、不跑脚本也可以：直接编辑 `go/<slug>/index.html` 里
> `content="0; url=…"` 和 `location.replace("…")` 两处，保持一致即可。

### 增删一个专题

在 `links.json` 的 `entries` 里加/删一条（`slug` 用小写英文），再跑一次脚本。
`qr/index.html` 里的卡片是手写的，改完记得同步加卡片，脚本会做一致性反查
（地址或图片路径对不上会直接报错，不会悄悄放过）。

## 5. 重新出图 / 印刷

```powershell
cd xiaohe-gudao-db
python -m pip install segno zxing-cpp   # 首次
python tools/make_qr.py                 # 生成 + 自检
```

自检会做五件事，任何一项失败都会退出码 1：

1. `links.json` 结构合法（slug 唯一、颜色合法、地址 ≤ 60 字符）；
2. `target` 指向的文件真实存在；
3. 每张 PNG 都能被 zxing 解码，且内容与预期 URL **逐字一致**；
4. 每张 PNG 四周留白（quiet zone）是纯白，没有被裁掉；
5. `qr/index.html` 里的地址与图片路径和 `links.json` 一致。

### 直接用

- 打印整张：`qr/print-a4.pdf`，A4 纵向，**按 100%（实际大小）** 打印，不要「适合页面」。
- 单枚放进排版：`qr/codes/<id>.svg`（Illustrator / Affinity / InDesign 直接置入，矢量）。
- 单枚贴进 Word / PPT：`qr/codes/<id>-print.png`。
- 屏幕上打开：<https://hpairr.github.io/xiaohe-gudao/qr/>（页面右上角有「打印 A4」按钮）。

### 印刷规矩（别省）

| 项 | 要求 |
| --- | --- |
| 边长 | 展签 ≥ 28 mm；展板远看 ≥ 35 mm；不要小于 20 mm |
| 颜色 | 黑码白底。**不要反白、不要半透明、不要加滤镜/纹理/圆角遮罩** |
| 留白 | 码四周至少留 4 个模块（生成的图里已经留好，裁切时别切掉） |
| 材质 | 哑光纸／哑光膜；亮膜反光会让手机对不上焦 |
| 位置 | 离地 1.2–1.5 m，正面平贴，别贴在弧面上 |

七个码都是 **ECC Q（25% 纠错）**、版本 4–5（33–37 模块），
`/qr/print-a4.pdf` 里约 31 mm 见方，模块约 0.69 mm，属于很宽松的印刷尺寸。

## 6. 上线前核对（三步）

```powershell
# 1) 本地：短链和落地页都能打开
curl.exe -s -o NUL -w "%{http_code}\n" http://127.0.0.1:8765/go/nushu/

# 2) 推送后：一条命令核对线上七个地址（全部 200 才会退出码 0）
python tools\make_qr.py --check --live

# 3) 手机实测：用微信「扫一扫」和系统相机各扫一张打印稿，
#    不要只对着屏幕扫
```

`--live` 现在会报 6 个 404 —— 那是**正常的**，短链还没推上去；
推送并等 Pages 构建完（仓库 Actions 变绿）以后再跑一次，全绿才去印刷。

站点自查仍用原来的：

```powershell
node tools\check-site.mjs
```

> 若 `check-site.mjs` 报 `index.html` / `database.html` 缺文件 `...`、`href, key`、`location.href`，
> 那是脚本把 JS 里的字符串误当资源路径了（这三条在本次改动前就有），
> 与二维码页面无关：`qr/index.html` 那一行应当是「缺失 0」。

## 7. 已知边界

- 短链是**目录形式**（`go/nushu/index.html` → `/go/nushu/`）。扫码不受影响；
  手打时带上结尾斜杠；漏了斜杠 GitHub Pages 会 301 补上，但别依赖这个行为。
- 跳转页依赖 `<meta refresh>` 或 JS，二者任意一个可用即可；
  两个都被禁用时（极老浏览器）页面上有可点的文字链接兜底。
- 二维码内容一旦生成就固定，**不要用短链服务**（如 bit.ly）——第三方挂了码就废了。
- 二维码图片本身不含任何统计参数，扫一次就是一次普通访问。
