## 一、布局选型（先选引擎，再动手）

| 场景 | 用什么 | 出处 |
| --- | --- | --- |
| 内容驱动、单轴、数量未知、要自动换行（导航、标签、跑马灯轨道） | **Flexbox** | [web.dev/layout](https://web.dev/learn/css/layout) |
| 结构驱动、行×列对齐到同一套栅格（页面骨架、卡片墙、图文行） | **Grid** | [MDN Grid 基本概念](https://developer.mozilla.org/zh-CN/docs/Web/CSS/CSS_grid_layout/Basic_concepts_of_grid_layout) |
| 单轴溢出裁剪 | `overflow` 双关键字（见第三节） | [MDN overflow-x](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-x) |

**不做的事**：不用 `float`、不用 `position:absolute` 去「把东西排成一行」——
absolute 只用于它本身的语义（浮层、吊挂物这种真的脱开文档流的元素）。

### Flexbox 必备两条

```css
.row { display:flex; flex-wrap:wrap; gap:8px; align-items:center; }
.row > .item { min-width:0; }   /* ← 必写：flex 项默认拒绝收缩到小于内容固有宽度 */
```

- **`min-width:0`**：长单词 / 长 URL 会把布局撑爆。这是 flex 最常见的坑。
- 用 `flex-basis` 而不是 `width`，grow/shrink 才可预测。

### Grid 必备两条

```css
.grid { display:grid; gap:16px;
        grid-template-columns: repeat(auto-fit, minmax(min(240px,100%), 1fr)); }
```

- **`minmax(0,1fr)` 而不是 `1fr`**：`1fr` 隐含 `minmax(auto,1fr)`，内容会把轨道撑破。
- `auto-fit`（折叠空轨道、拉伸填满）用于卡片墙；`auto-fill`（保留空轨道）用于日历式栅格。

**Grid/Flex 容器里 margin 不塌陷**（[web.dev/spacing](https://web.dev/learn/css/spacing) 原文：
flex 容器里「margins are combined, instead of collapsed」）——
这意味着**容器内间距一律用 `gap`，不要用 margin**：gap 不会塌陷、不用处理「最后一个元素多出外边距」。

## 二、间距系统（本项目实际的坑）

**规则：间距只用 `gap` 或 `padding`；`margin` 只用于「把组件从邻居旁边推开」这种块级间距。**

### 我犯过的错（写下来别再犯）

> 为了让「带子上的点位」和「悬挂点」对齐，我写了
> `padding-bottom:10px` + `margin-top:2px` + `.tassel{margin-top:-11px}` 这种补偿式对齐。

为什么不行：这是**用像素试错去凑对齐**，依赖四个隐式值
（`line-height:1.6` 的行盒高度、`font-size:28px`、`gap`、边框），
任何一处改动（换个字体、改字号、改行高）都会让它错位，而且错多少完全靠猜。

**正确做法**（任选其一，都能做到确定性对齐）：

1. **同一容器 + gap**：把点位列和悬挂点放进同一个 Grid/Flex 容器，用 `gap` 控制行距，
   悬挂点用 `grid-row` 落到指定行——对齐由栅格保证，不是算出来的。
2. **`position:relative` 的绝对量**：悬挂点用 `position:absolute; inset-block-start:<行高>`，
   值从一个 token 取（例如 `--rail-y`），两处引用同一个变量。
3. **干脆不做「点位」**：丝缕只按固定间距铺满一行（`left = i × span`），
   不需要与任何东西对齐——**对齐需求消失，问题就消失**。

> 本项目最终采用 3：丝缕间距由 JS 量出轨道循环长度后均分，
> 不再依赖任何「点位」元素，也就没有对齐问题。

### 间距刻度

只用 **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96**，写进 CSS 自定义属性：

```css
:root{ --sp-1:4px; --sp-2:8px; --sp-3:12px; --sp-4:16px;
       --sp-6:24px; --sp-8:32px; --sp-12:48px; --sp-16:64px; }
```

禁止随手写 13px、17px、26px 这种不在刻度上的值。
（本项目旧代码里 `padding:28px 0`、`margin-bottom:26px`、`gap:22px` 都是这么来的。）

## 三、单轴溢出裁剪（本项目最严重的错）

[MDN `overflow-x`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-x) 原文：

> If `overflow-y` is `hidden`, `scroll`, or `auto`, and the `overflow-x` property is `visible`
> (default), **the value will be implicitly computed as `auto`.**

意思是：**你没法只关一轴。** 写了 `overflow-x:hidden` 而不管 `overflow-y`，
纵向的 `visible` 会被浏览器改成 `auto` —— 于是纵向也被裁掉了。

### 结论：要「横着裁、竖着不裁」，必须用双关键字

```css
.clip{ overflow:hidden visible; }   /* x 裁，y 放出去 */
```

支持情况（[MDN 兼容表](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow-x)）：
Chrome 68+ / Edge 79+ / Firefox 61+ / Safari 13.4+，2020 年起全绿。

### 另一个选择：`overflow:clip`

`clip` 与 `hidden` 的区别（MDN）：
- `clip` **禁止一切滚动**（包括 `scrollLeft` 这类编程滚动），**不建立滚动容器**，
  **不创建新的格式化上下文**；
- `hidden` 仍然是可以编程滚动的滚动容器，会建立 BFC。

对装饰性裁剪（跑马灯）**首选 `clip`**：不会意外产生可达的滚动容器，
也不会因为 BFC 影响 sticky 定位。

### 本项目怎么改的

原来（错）——把跑马灯和丝缕拆成两个块，各自 `overflow:hidden`，靠负 margin 拼回去：

```css
.marquee{overflow:hidden}          /* 横竖都裁了 */
.tassel{overflow:hidden;margin-top:-11px}   /* 于是只能另起一块再叠回去 */
```

现在（对）——一个裁剪盒负责横向，纵向放出去让丝缕垂下来：

```css
.marquee{overflow:clip}                    /* 外层：不产生滚动容器 */
.marquee-clip{overflow-x:hidden;overflow-y:visible}  /* 横裁、纵放 */
.tassel{ /* 就在同一个流里，不需要任何负 margin */ }
```

## 四、渲染性能（本条我正好是反面教材）

[MDN `will-change`](https://developer.mozilla.org/zh-CN/docs/Web/CSS/Reference/Properties/will-change) 原文：

> **`will-change` 应该被视为最后的应对手段**，用于解决现有的性能问题。
> **不应该被用来预测性能问题。**
> **不要将 will-change 应用于过多的元素**……过度使用将导致内存使用过多，并导致更复杂的渲染发生。

而且它有个隐蔽副作用：**`will-change: transform` 会建立一个新的层叠上下文**
（MDN：给具体属性名时「建立新的合成层或新的层叠上下文」），
会把你子元素的 `z-index` 困在局部。

**我的错误**：给 22 个丝缕元素全加了 `will-change:transform`，纯属预防性滥用。

**规则**：
- 默认**不写** `will-change`。
- 只给「确实在动、且实测掉帧」的元素加，并且**用脚本在动画前后开关**，
  不要写死在样式表里：

```js
el.addEventListener('pointerenter', () => { el.style.willChange = 'transform'; });
el.addEventListener('animationend',  () => { el.style.willChange = 'auto'; });
```

### 高频次动画：优先 CSS 驱动，不要每帧写样式

- 能用 CSS 动画 / 滚动驱动动画（`animation-timeline`）解决的，别用 JS 每帧改 `left/top`。
- 必须用 JS 时：**只改 `transform` / `opacity`**（合成层属性），别改 `left`、`width`、`margin`。
- 本项目丝缕的横向位置是必须用 JS 的（要走「带子位移取模回绕」），
  所以**改的是 `transform: translate3d()` 而不是 `left`** —— 这是对的。

## 五、可访问性（装饰性内容必须对辅助技术隐藏）

[W3C ACT 规则 46ca7f](https://www.w3.org/WAI/standards-guidelines/act/rules/46ca7f/)：
标记为装饰的元素不应进入无障碍树。

**规则**：
- 纯装饰容器 / 图形：`aria-hidden="true"`（本项目跑马灯、丝缕、底纹都加了）。
- 装饰性 `<svg>` 同时加 `aria-hidden="true"`，不要留空 `role="img"`。
- 有语义的图形（如专题页首屏那种说明性插图）才给 `role="img"` + `aria-label`。
- 动画：`@media (prefers-reduced-motion: reduce)` 必须关掉或降级——
  本项目的做法是不跑物理循环，改用一份极轻的 CSS 摆动兜底。
- 触控目标 ≥ 44×44px；正文对比度 ≥ 4.5:1。

## 六、响应式

[web.dev](https://web.dev/learn/css/) + 本技能库 `web-layout` 的共识：

1. **移动优先**：基础样式写窄屏，`@media (min-width:…)` 只做增强。
2. **断点跟内容走**，每个断点都要有「这里确实需要变」的理由。
3. **能不用媒体查询就不用**：
   - 流式字号 `clamp()`：`font-size: clamp(1rem, .9rem + .6vw, 1.5rem)`
   - 自适应列数 `repeat(auto-fit, minmax(min(240px,100%),1fr))`
4. 移动端高度用 **`100dvh`**，不用 `100vh`（iOS Safari 地址栏会算错）。
5. 图片/视频/`svg` 全局 `max-width:100%; height:auto`，防横向滚动。
6. `scrollbar-gutter:stable` 防滚动条出现/消失引起跳动。

## 七、层叠上下文与 z-index

- `z-index` 只在**同一层叠上下文**内比较。
  `transform` / `filter` / `opacity<1` / `position:fixed` / `backdrop-filter` /
  `will-change` / `contain` **都会创建层叠上下文**。
- 排查口诀：明明 z-index 更大却不显示 → 找它与对手**最近的共同祖先里谁创建了层叠上下文**。
- 干净做法：`z-index` 只给顶层（header 50、浮层 100、toast 200），内部一律不写；
  需要隔离就 `isolation:isolate` 自建上下文，不要靠加大数字。

## 八、本轮实测记录（跑马灯 + 悬挂丝缕）

改完后用 headless Chrome + CDP 实测的数值，写下来供回归对照：

| 项目 | 实测值 |
| --- | --- |
| 挂点是否落在横杆上 | 横杆 Y=951.3，挂点 Y=952.8 → **在杆上**（差 1.5px，是菱形挂结自身高度） |
| 丝缕横向是否跟着带子走 | 带子 `translate3d(-404.56px)` 时丝缕整体左移同样位移 → **跟着走** |
| 丝缕是否会被绕出屏幕 | 回绕长度改用**容器宽度**后，各时刻均 **12/12 根在屏内** |
| 相邻间距 | 稳定 **112px**（= 循环长度 ÷ 点位个数） |
| 循环接缝 | 循环长度 1329 = 轨道宽 2658 ÷ 2 → **无缝** |
| 词间距 | 等宽列（`.mq-item` 左右各 40px padding），词间距 204/239/275px 随字数变化 → 节奏均匀、不再挤在一起 |
| 摆幅 | 滚动中峰值 **±16°** |
| 丝缕弯曲 | 中心线为二次曲线，弯曲量 **±15px**（clamp 上限）；小角度按比例、大角度封顶 |
| 控制台 | 主页 + 6 个专题页 + 8 条站内路由，**全部 0 报错** |

### 这一轮改错的三处（都记进规范，别再犯）

1. **自定义属性没定义 → 整条声明失效**。`gap:var(--sp-16)` 里的 `--sp-16` 从未定义，
   浏览器在 computed-value 阶段判定该声明无效，`gap` 悄悄变成 `normal`
   —— 跑马灯的词因此**一点空隙都没有、全挤在一起**。
   **规则**：用 `var()` 之前先确认 token 存在；token 一律集中在 `:root` 定义，不要散落。
2. **横向回绕用错了长度**。一开始按「循环长度」（672px）取模，而容器宽是 1258px
   —— 一半丝缕被绕到屏幕外。**正确做法：按容器宽度取模**。
3. **用负 margin 凑像素对齐**。为了让挂点落到横杆线上，先写了
   `padding-bottom + margin-top + margin-top:-11px` 这种补偿，依赖 4 个隐式值。
   **正确做法**：先让结构上它们本来就在同一行（同一容器 + gap），
   剩下的 1~2px 用**一个** grid 行高或一个 token 控制，不叠加补偿。

### 关于「丝没有曲线」与「像撞墙一样弹回」

这两条是同一个病根：**用「角度」去描述一根丝**。

- 只做 `rotate` → 看起来是一根硬棒在转，没有丝的形变；
- 给角速度加硬钳位（超限就把速度反向）→ 一到大角度就「撞墙弹回」；
- 按角度画一条二次曲线 → 那是**假曲线**，弯得再顺也和动力学无关。

前两版我一直在「调角度参数」，方向就错了。**正确做法是照成熟的绳索模拟来写。**

用的是 **Thomas Jakobsen《Advanced Character Physics》**（IO Interactive，Hitman 的物理系统）：
https://www.cs.cmu.edu/afs/cs/academic/class/15462-s13/www/lec_slides/Jakobsen.pdf

论文给的三件可照抄的东西：

```
① Verlet 积分：  x' = 2x − x* + a·Δt²      // 不存速度，天然稳定，能量自然耗散
② stick 约束：   每帧把每段长度拉回 restLength   // 论文 §4
③ 松弛迭代：     迭代 K 次逐个满足局部约束，收敛到全局解；最后把顶端压回锚点
```

本项目实现（`tasSimulate` / `tasRender`）：

- 每根丝 = 8 个质点，相邻两点一根刚性杆（`TAS_SEG = 14px`）
- 每帧 14 次约束松弛（`TAS_ITER`），保证被甩时也不被拉长
- 驱动：带子的**横向加速度**作用在锚点上（`TAS_RAIL_K`），惯性把丝甩向反方向
- 重力 `TAS_GRAV = 3200`、线性阻力 `TAS_DRAG = 0.075`、气流 + 高频微扰
- 渲染：按结点画一条二次贝塞尔穿过的平滑曲线

**所以：没有角度概念、没有钳位、没有假曲线。**
弯曲与下垂全部由重力 + 约束迭代自己长出来。

**实测**（驱动过程中记录「上端 / 中点 / 末端」的横向位移）：

| 时刻 | 上端 | 中点 | 末端 | 弯曲量 |
| --- | --- | --- | --- | --- |
| 250ms | 2.9px | 11.8px | 24.4px | 0.6px |
| 750ms | 7.8px | 27.0px | 52.3px | 1.9px |
| 1500ms | 11.3px | 41.1px | 78.2px | 2.8px |

- **越往下位移越大**（11 → 41 → 78px）→ 这才是悬挂物，不是整根一起转
- 静止时总长 110.4px（丝长 110px）→ **约束有效，丝不会被拉长**
- 弯曲量峰值 4.9px（旧的假曲线模型只有 0.46px）
- 摆周期 ≈ 1.2s、阻尼比 ≈ 0.13 → 停手后自己晃几秒才停
