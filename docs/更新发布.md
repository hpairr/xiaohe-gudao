线上最初的文件**是用网页「Add files via upload」直接传的**（3 个提交），
和本地这个 git 仓库没有共同祖先。所以在这种状态下一上来就 `git push` 会被拒。

已经处理过：本地 HEAD 已对齐到线上的 `43b231b`，新提交 `c169130` 是它的直接子提交，
因此正常推送即可，**不需要** `--force`。

以后每次更新都从这条线上历史往后接，不要再回头用网页上传，
否则又会产生第二条互不相干的历史。

## 1. 网络这一关（国内访问 GitHub 的老问题）

现象：`github.com` 解析到 `20.205.243.166`，443 端口握手后数据被重置，浏览器和 git 都连不上；
但 `api.github.com`、`ssh.github.com`、`hpairr.github.io` 都正常。

### 方案 A：改 hosts（一次到位，需要管理员）

在**管理员** PowerShell 里执行：

```powershell
$h = "$env:SystemRoot\System32\drivers\etc\hosts"
Copy-Item $h "$h.bak" -Force
Add-Content $h "`r`n140.82.113.3 github.com`r`n140.82.113.3 www.github.com"
ipconfig /flushdns
```

验证：`curl.exe -I https://github.com` 返回 `200` 或 `301` 即可。

> 这个 IP 不是永久的。哪天又连不上，重新试这几个：
> `140.82.112.3` / `140.82.113.3` / `140.82.114.3`，哪个通换成哪个。
> 撤销：删掉 hosts 里那两行（或用 `hosts.bak` 还原）。

### 方案 B：走代理

```powershell
git config --global http.proxy http://127.0.0.1:7890   # 端口按你实际软件改
git config --global https.proxy http://127.0.0.1:7890
# 不用了要清掉：
# git config --global --unset http.proxy
# git config --global --unset https.proxy
```

### 方案 C：只让 git 能连（不解决浏览器登录）

```powershell
git config http.curloptResolve "github.com:443:140.82.113.3"
```

只对 git 生效，`git fetch` / `ls-remote` 立刻可用；但**首次 push 要登录，
登录窗口要在浏览器里打开 github.com**，所以还是得先有 A 或 B。

## 6. 出问题怎么退

| 情况 | 处理 |
| --- | --- |
| `! [rejected] ... non-fast-forward` | 别强推。先 `git fetch origin`，再 `git rebase origin/main` 后重推 |
| 推错了想回退 | 线上：仓库页 → Commits → 找到上一个提交 → 本地 `git reset --hard <sha>` → 重推；或网页 Revert |
| 本地旧提交丢了 | `git reflog` 里能找回（默认保留 90 天）；对齐前的 `6aced78` 就是旧的本地首提交 |
| Pages 404 | Settings → Pages 确认分支是 `main`、目录是 `/(root)`，等 2 分钟再刷 |
