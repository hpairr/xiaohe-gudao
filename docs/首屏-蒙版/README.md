# 首屏：一整张风景，四字是蒙版上的窗

首页 `index.html` 的 00 首屏。2026-10-30 第三版：**去掉纸从下面漫上来的水线**，
改成「照片整体褪成纸 + 字从比屏幕还大拉回到定稿」。

看效果：`index.html?nofx&intro=1&hp=0.32`
（`hp` 把首屏钉在某个进度上，0 = 只有照片，1 = 定稿。看稿、截图、答辩演示都用它。）

- `01-只有照片.jpg` — p=0，整屏就是照片，没有一个字
- `02-字比屏幕大.jpg` — p=0.32，字 1.6 倍，左右溢出画面
- `03-定稿.jpg` — p=1
- `04-窄屏大字.jpg` — 390×844，p=0.2（窄屏 2×2 排法）
- `05-宽屏定稿.jpg` — 2560×1250

## 机制

```
.h6-photo   整张风景，background-attachment:fixed，铺满视口
.h6-veil    一张纸盖在上面，opacity 0→1（均匀淡化，没有任何边线）
.h6-title   真 <h1>「潇贺古道」，底图与 .h6-photo **同图同参数**，
            再用 background-clip:text 把字切成窗口
```

纸透的时候，字与照片逐像素重合 → **字看不见**；纸越实，字越是画面里唯一还黑的东西，
于是浮出来。所以"一开始只有图片"不是靠透明度藏起来，而是靠几何重合。

滚动进度（`p = 已滚动 / (首屏高 - 一屏)`，首屏 280svh，一屏 900 高时约 1620px）：

| p | 发生什么 | 对应滚动距离 |
| --- | --- | --- |
| 0 – .05 | 只有照片 | 0–80px |
| .05 – .62 | 照片整体褪成纸（字同步从背景里"变黑"，没有水线、没有边） | 80–1000px |
| .05 – .82 | 字从 **1.7 倍**（比屏幕宽 35%，最外两字各溢出三成）拉回到 1 倍 | 80–1330px |
| .78 – .88 | 细线 + 落款「富川秀水村 · 石拱桥」 | 1260–1425px |
| .46 – .56 | 顶栏淡回（开场先退场：淡化中段浅字深字都不稳） | 745–905px |

### 为什么把淡化拉这么长

一版把淡化压在 264px 里，一次滚轮（约 100px）亮度就跳约 **98 级**，看起来像"闪一下"。
现在摊到约 920px，同样一格只走 **约 25 级**，中途随便停都还是好看的"雾里透字"。
再嫌快，只改 `setHero` 里那一行 `smoothstep(0.05, 0.62, p)` 的第二个数（往 0.75 走）。

窄屏（≤760px）四字排 2×2，倍数上限收到 **1.45**：2 倍时一屏只剩四条竖杠，读不出字。

## 硬约束：这一段不能出现任何 transform

`background-attachment: fixed` 一旦碰上 transform（元素自己或**任何祖先**），
定位基准就会从视口改成那个元素自己，字的底图立刻和照片层错位 —— 字会提前露出来。

三张实测图（一次性夹具，已删）：

- 无 transform：与底图逐像素比对 **maxdiff = 0**（完全重合）
- 元素自己 `translate(-50%,-50%)`：maxdiff 227，28.6 万像素不同
- 祖先 `scale(1.4)`：maxdiff 224，18.2 万像素不同

所以：缩放走 **font-size 动画**，居中走 **flex**，不用 `translate(-50%,-50%)`。
另外 `.h6-title` 必须 `flex:none`，否则窄屏 2×2 放大时会被 flex 压窄，
退化成"每行一个字"的竖排，跟定稿版式对不上（踩过）。
以后再想加指针视差、hover 放大之类，先想清楚这一条。

## 已知限制

- **iOS Safari / 部分安卓浏览器不支持 `background-attachment: fixed`**：会把 fixed 当 scroll，
  字的底图改按字自己的盒取景，于是 p=0 时字不再与照片重合 —— 手机上开场会先看到
  "照片纹理的字"，而不是"只有照片"。桌面 Chrome / Edge / Firefox 正常。
- 缩字走 font-size 动画（不是 transform），每帧要重排 + 重绘这块题名。
  1440×900 下测量无卡顿，但低端机滚动时留意一下。
- `?hp=` 是调试参数，别写进对外链接。
